## Q1: What should the Flutter project be named (and where does it live)?

A. App directory `hello_world` at the repo root; Dart package name `hello_world`.
B. App directory `hello_world` under a new `examples/` folder; package `hello_world`.
C. App directory `hello_world` under `apps/`; package `hello_world`.
D. Use a different name (describe it).
X. Other (describe)

[Answer]: A — `hello_world` at the repo root, package `hello_world`.

## Q2: Which platform must the example be verified on?

A. Desktop only (whatever is available locally: macOS/Linux/Windows).
B. Web only (`flutter run -d chrome` / `flutter build web`).
C. Desktop plus one mobile target.
D. Any single supported target — pick the first available.
X. Other (describe)

[Answer]: A — desktop only, using the locally available target.

## Q3: What Material/widget baseline should the example use?

A. Flutter defaults as generated by `flutter create` (Material 3, `useMaterial3` default).
B. Explicitly pin Material 3 (`useMaterial3: true`).
C. Explicitly pin Material 2 for maximum compatibility.
D. No `MaterialApp` — a bare `WidgetsApp` to show the smallest possible app.
X. Other (describe)

[Answer]: A — Flutter defaults from `flutter create` (Material 3).

## Q4: How strict should static analysis be?

A. Keep the default generated `analysis_options.yaml` (`flutter_lints`).
B. Require `flutter analyze` to report zero issues (add as an acceptance criterion).
C. Add stricter lints beyond `flutter_lints`.
D. No analysis requirement.
X. Other (describe)

[Answer]: A — keep the default `flutter_lints` `analysis_options.yaml`.

## Q5: What automated test coverage is required for this example?

A. One widget test asserting "Hello World" renders.
B. A widget test plus a unit test (e.g. a pure greeting function).
C. Widget test with a golden-file assertion on the rendered screen.
D. No test requirement beyond `flutter test` running successfully (even if empty).
X. Other (describe)

[Answer]: A — one widget test asserting "Hello World" renders.
